# liquidity-risk-engine-go

完全本地运行的流动性风险计量与压力测试引擎：以本地头寸与合同数据模拟资金来源与运用，
按版本化情景输出可解释、可复现的流动性结论。无任何外部服务、网络依赖或真实凭据。

## 构建与验证

```bash
go build ./...                 # 构建
go test ./...                  # 单元测试
CGO_ENABLED=1 go test -race -v ./...  # race 检测 + 业务覆盖日志
go run ./cmd/demo              # 端到端示例
```

`go test -v` 日志中以 `[头寸校验]`、`[分桶确定性]`、`[情景版本]`、`[回填与冲正]`、
`[幂等重放]`、`[并发一致性]`、`[快照隔离]` 等标签标明各业务链路的用例与结果。

## 工程结构

| 文件 | 职责 |
|---|---|
| `types.go` | 头寸模型、方向口径、可区分拒绝原因（`RejectError`/`RejectCode`） |
| `bucket.go` | 时间桶定义与现金流阶梯（`Ladder`） |
| `expand.go` | 行为假设集与头寸→合同/行为现金流展开 |
| `scenario.go` | 版本化情景注册表、校验、确定性叠加链 |
| `metrics.go` | 压力净现金流、LCR、生存期 |
| `store.go` | 追加式事件日志 + MVCC 快照（原子批次、幂等重放） |
| `engine.go` | 对外门面：摄取、快照、情景计算、结论缓存 |
| `cmd/demo` | 本地端到端示例 |

## 头寸与现金流口径

- 金额一律为整数最小货币单位（`Money`，分），保证分桶结果与登记顺序无关。
- 方向口径（银行视角）：存款/批发融资/未提取授信为 `OUTFLOW`，证券/贷款回款为 `INFLOW`；
  头寸声明的 `Direction` 与类型口径不符即以 `DIRECTION_MISMATCH` 拒绝。
- 活期存款与未提取授信为开放式期限，不得携带到期日；其余类型必须有 `StartDate < MaturityDate`。
- 输入不做任何静默兜底：缺字段（`MISSING_FIELD`）、金额非正（`INVALID_AMOUNT`）、
  期限非法（`INVALID_TENOR`）、重复登记（`DUPLICATE_POSITION`）均以可区分的原因拒绝，
  且整个批次原子失败，不留半截状态。
- 时间桶：`OVERNIGHT, D2_7, D8_14, D15_30, D31_90, D91_180, D181_365, GT_1Y`。
  同一头寸同一天的分桶是纯函数（头寸, 假设, asOf），聚合前按头寸 ID 排序，
  与登记顺序无关。任意时点净现金流经 `Engine.NetCashflowAt` 查询。

行为展开规则（假设均为 [0,1] 比率，缺失即拒绝情景）：

- 活期存款：runoff 部分计入隔夜流出，稳定核心计入 >1Y。
- 定期/批发融资：到期时仅 (1-续作率) 部分流出。
- 未提取授信：压力提取率部分计入隔夜流出。
- 证券：不计合同流，按 (1-折扣率) 计入 HQLA； horizon 内到期计入流入。
- 贷款：提前还款率部分计入即期流入，余额到期流入。

## 情景与版本语义

- 情景以 `(ID, Version)` 唯一标识，版本一经发布不可变、不可覆盖重发。
- 根情景必须给出完整假设集（任何参数缺失即 `SCENARIO_INVALID` 拒绝）；
  叠加情景（overlay）必须钉住 `(Base, BaseVersion)` 且至少覆盖一个字段。
- 多情景叠加规则确定：沿钉住的版本链自底向上、逐字段覆盖，绝不混算新旧假设。
- 比率越界 [0,1]、引用未定义基情景（`UNKNOWN_SCENARIO`）等均明确拒绝。
- 结论按 `(快照序列, 情景ID, 情景版本)` 缓存：历史版本结论可原样复现，
  新版本只产生新结论，不改写旧结论。

## 指标

- 压力净现金流阶梯：展开后按桶加总的符号化现金流。
- LCR = HQLA / 30 日压力净流出（无流出时记为 n/a）。
- 生存期：以 HQLA 为初始缓冲，逐桶累计净现金流，首次转负所在桶的末位天数
  （400 天 horizon 内未耗尽显为 400）。

## 快照与更正规则

- 摄取单位为批次（`Batch`）：整批校验、整批提交、单次原子发布，
  任何读操作不会看到只应用了一半的批次。
- 事件类型：`BOOK`（登记）、`CORRECT`（更正，可回填历史业务日期）、`REVERSE`（冲正）。
  更正/冲正只产生新的状态序列号，已发布快照永远不变。
- 幂等：`BatchID` 重放为已报告的无操作（`ApplyResult.Duplicate=true`），不重复计数；
  事件 ID 全局去重，跨批次复用即拒绝。
- 对已发布快照重复计算结论逐位一致；后续更正只影响新快照。

## 并发一致性模型

- 写路径：提交在互斥锁内完成，先克隆不可变状态、整批应用、再一次原子指针发布。
- 读路径：快照是 O(1) 的原子指针加载；指标计算在锁外对不可变状态进行，
  耗时计算不阻塞任何写入与查询。
- 结论缓存读写分离（`RWMutex`），同一键并发计算只发布一次。
- 并发用例不使用 sleep，仅靠 `WaitGroup`/channel 同步，在 `-race` 下稳定通过。
